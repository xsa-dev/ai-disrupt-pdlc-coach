## CHANGED Requirements

### Report Text Formatting (Telegram MarkdownV2)

The diagnosis text report sent to Telegram must render with correct MarkdownV2 formatting and must never show visible escape sequences for formatting characters.

#### Requirement: Correct MarkdownV2 rendering for structure
- Bold headers must render as bold (using `*text*`).
- Lists must render properly using `•`.
- No formatting characters should appear escaped in the final message.

#### Scenario: Bold and lists render correctly in chat
- GIVEN a completed diagnosis
- WHEN the report is generated by `generate_diagnosis_markdown` and sent with `parse_mode="MarkdownV2"`
- THEN the user sees proper bold section titles (e.g. *Ключевые показатели*) and clean bullet lists
- AND the message does not contain visible `\*\*`, `\-`, `\(` or similar

#### Scenario: Selective escaping of content only
- GIVEN dynamic content (justification, strengths, gaps, recommendations, team name) that may contain special characters
- WHEN `_escape_md_v2` (or equivalent logic) is applied
- THEN only literal content is escaped
- AND Markdown formatting syntax (`*`, `_`, `•`) used for structure remains unescaped

#### Scenario: Graceful fallback when MarkdownV2 fails
- GIVEN that sending with `parse_mode="MarkdownV2"` fails (e.g. due to length or parsing error)
- WHEN the bot falls back to plain text
- THEN the report text remains human-readable without double-escaped characters

### PDF Report Layout and Presentation

PDF reports are generated by a dedicated `DiagnosisPDF` subclass of FPDF with proper `header()` and `footer()` methods, ensuring consistent layout across multiple pages.

#### Requirement: Proper multi-page support with headers and footers
- A custom `DiagnosisPDF` class implements `header()` and `footer()`.
- On page 1: large title with team name.
- On subsequent pages: compact header with team name + separator line.
- Every page has a footer: "Disrupt PDLC Coach • 2026 | Страница N".
- Margins and auto_page_break are configured to leave space for footers.

#### Scenario: Long recommendations and justification do not overflow
- GIVEN long text in "Обоснование" or "Рекомендации и gate-критерии"
- WHEN `generate_diagnosis_pdf` renders the document using `DiagnosisPDF` + `multi_cell`
- THEN the full text flows across pages using proper wrapping without being cut off at edges (verified by pdftotext / visual).

#### Requirement: Excerpt section must never be empty
- The header "Релевантные выдержки из белой книги" MUST only be printed when there is actual content.
- The system MUST include 1–2 excerpts.
- Each excerpt (or their combination) should be substantial — target total length that occupies approximately half a PDF page when rendered (roughly 600–900+ characters of readable text across the excerpts).
- If the grounding module returns weak results, fallback logic MUST provide at least one meaningful excerpt from the whitepaper.

#### Scenario: Book excerpts are always present and fill meaningful space
- GIVEN a completed diagnosis
- WHEN `generate_diagnosis_pdf` is called
- THEN the PDF contains the section "Релевантные выдержки из белой книги"
- AND inside it there are 1 or 2 real quoted excerpts (not empty)
- AND the excerpts are long enough to be useful (hundreds of characters each, ideally ~half page combined)
- AND they are rendered distinctly as quotes (italic or styled, with « »)
- AND there is no case where the header appears with nothing below it

#### Scenario: Professional headers and footers on all pages
- GIVEN any diagnosis PDF (1 or more pages)
- WHEN the document is generated with `DiagnosisPDF`
- THEN every page contains:
  - Appropriate header (full title on page 1, compact on continuation pages)
  - Consistent footer with "Disrupt PDLC Coach • 2026 | Страница N"
- AND section headers use consistent styling

#### Scenario: Multi-page reports handle pagination cleanly
- GIVEN a report that requires more than one page
- WHEN generated with `set_auto_page_break` and header/footer methods
- THEN content flows naturally; continuation pages have proper headers; no content is lost at page breaks



#### Requirement: Excerpts must be present and substantial (no empty section)
- The PDF MUST always include the section "Релевантные выдержки из белой книги".
- The section MUST contain 2 excerpts.
- Excerpts should be long enough to occupy a significant portion of the page (target ~half a page combined when rendered at 9-10pt).
- If the dynamic retrieval fails, hardcoded or fallback excerpts from the whitepaper MUST be used so the section is never empty.
- Excerpts are rendered as distinct quoted blocks with « ».


## Implementation Notes
- Primary file: `coach/core/report.py`
  - `_escape_md_v2` function needs to become selective
  - `generate_diagnosis_markdown` needs cleaner separation of structure vs content
  - `DiagnosisPDF` (subclass of FPDF) implements header/footer + page numbers. Content uses multi_cell + sensible font sizes.
- Sending logic: `coach/telegram/diagnosis_bot.py` (in `finish_diagnosis`)
- Consider extracting a small `ReportFormatter` class for better testability

## Verification Methods
- Manual: Run full `/diagnosis` flow in Telegram and inspect both text message and received PDF.
- Automated: Unit tests for `generate_diagnosis_markdown` that assert no visible escape sequences in output.
- PDF verification: Use `pdftotext` + length checks or simple visual review of generated files.
- Edge cases: Test with very long recommendations and multi-line excerpts.

## Non-Requirements
- Visual redesign (colors, images, charts, custom fonts beyond DejaVu)
- Changes to assessment logic, L/R levels, or question text
- Support for HTML, DOCX, or other output formats
- Advanced layout features (tables, columns, background graphics)
