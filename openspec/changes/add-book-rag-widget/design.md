## Context

GitHub Pages обслуживает статический справочник. RAG backend работает отдельно на cloud-ru; его контракт — iframe-чат с источниками и диагностикой. Текущий SHA исходников сайта проверен; незавершённые серверные изменения исключены из кандидата.

## Goals / Non-Goals

Goals: добавить лениво загружаемый диалог по книге на странице диагностики, сохранить контроль пользователя и проверяемые источники.

Non-Goals: передавать диагностические профили автоматически, переносить ключ в браузер, изменять вычисление уровней L/R.

## Decisions

- Использовать iframe отдельного HTTPS-приложения и Shadow DOM для кнопки и контейнера. Это сохраняет изоляцию от Tailwind и контактного виджета; прямая вставка интерфейса потребовала бы совместного управления стилями и API.
- Запускать загрузку только по нажатию. До открытия пользователь не создаёт обращения к backend.
- Ключи и дневной лимит остаются на сервере. В allowlist Pages добавляется только конкретный JS, а не каталог произвольных файлов.
- Разместить кнопку выше существующей кнопки связи и обеспечить закрытие кнопкой и Escape.

## Risks / Trade-offs

- Недоступный backend → состояние ошибки в чате, основная диагностика работает самостоятельно.
- Общедоступный платный API → сохраняемый дневной лимит и ограничение параллелизма на backend.
- Смена hostname или префикса → URL хранится в data-атрибуте; виджет сохраняет путь /pdlc/.

## Migration Plan

Сначала проверить backend по публичному HTTPS, затем добавить статический виджет и точный allowlist. Пройти проверки и публикацию Pages; подтвердить диалог на реальном origin. Откат — убрать единственный script из diagnosis.html и JS из allowlist; серверный релиз имеет отдельный откат.
