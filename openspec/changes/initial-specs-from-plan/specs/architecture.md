# Архитектура Disrupt PDLC Coach

## Overview
Описание высокоуровневой архитектуры инструмента, чтобы все последующие реализации и расширения следовали единым принципам.

## Requirements

### ARCH-1. Основные компоненты
- **Knowledge Base (RAG)** — см. отдельный spec.
- **Team Context Store** — персистентное хранилище профилей команд, roadmap, артефактов.
- **Core Coach** — основной агент с сильным system prompt, заточенным под принципы книги.
- **Tools / Functions** — набор инструментов для диагностики, генерации roadmap, оценки практик, создания спецификаций.
- **Telegram Adapter** — слой взаимодействия (команды, ведение диалогов, форматирование).
- **Guardrails** — слой проверки ответов на соответствие принципам AI-Disrupt PDLC.

### ARCH-2. Двухпетлевая модель в самом агенте
- Петля намерения: пользователь (команда) формулирует цель (диагностика, roadmap, проектирование).
- Петля реализации: агент выполняет работу по генерации артефактов.
- Встроенная валидация: guardrails + возможность пользователя корректировать.
- Governance: строгие правила (например, "никогда не рекомендовать менять модель вместо среды").

### ARCH-3. Хранение состояния
- Поддержка долгосрочного контекста по командам.
- Возможность передачи сессии между разговорами (аналог Session Handoff).
- История артефактов и изменений уровней.

### ARCH-4. Расширяемость
- Легкое добавление новых сценариев.
- Легкое добавление новых инструментов.
- Подготовка к добавлению внутренних знаний без ломки grounding по книге.

## Implementation Notes
- Рекомендуется реализовывать как отдельный skill в Hermes.
- Использовать векторное хранилище для RAG (с метаданными).
- State machine или явное управление сессиями сценариев.

## Non-Goals (первой версии)
- Полноценная платформа IDP.
- Сложная мультиагентная оркестрация (A2A и т.д.) до достижения L3+.
