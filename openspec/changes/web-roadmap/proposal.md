# Web Roadmap Page

## Summary
Создать отдельную веб-страницу `roadmap.html` для построения и просмотра Roadmap трансформации команды по методологии AI-Disrupt PDLC. Страница должна работать как самостоятельный инструмент и интегрироваться с текущей diagnosis.html.

## Motivation
- После MVP диагностики (mvp-diagnosis-scenario) следующим естественным шагом по спекам является SR-2 — построение Roadmap.
- Пользователь сейчас фокусируется только на веб-странице (не на Telegram-боте).
- Нужен удобный визуальный инструмент, которым команда может пользоваться независимо или сразу после диагностики.
- Roadmap — один из самых ценных артефактов для команд (показывает путь Lx → Ly с конкретными практиками и gate'ами).

## Goals
- Реализовать чистую, красивую веб-страницу roadmap.html в стиле diagnosis.html.
- Поддержка двух режимов ввода:
  - Автоматически из результата диагностики (через URL-параметры или localStorage).
  - Ручной выбор текущего и целевого уровня.
- Генерация реалистичного roadmap с этапами согласно книге:
  - Учёт временных горизонтов (L0→L1: дни, L1→L2: 1-3 мес, L2→L3: 6-12 мес, L3→L4: 12-18 мес).
  - Ключевые практики на каждом этапе.
  - Gate-критерии перехода.
  - Риски и антипаттерны.
- Красивая визуализация (timeline / карточки этапов).
- Возможность экспорта (PDF / Markdown).
- Ссылка на белую книгу.
- Интеграция с diagnosis.html (кнопка "Построить Roadmap" после диагностики).

## Non-Goals (для этого change)
- Полноценный Telegram-бот с /roadmap.
- Сложный RAG или динамическая генерация на основе всей книги (пока hardcoded на базе уровней + типичные практики).
- Сохранение roadmap в профиль команды (позже).
- Мульти-командность на этой странице.

## Scope
- Новая страница: `web/roadmap.html`
- Обновление `diagnosis.html` — добавление кнопки перехода на roadmap с передачей результата.
- Базовая логика генерации roadmap в JS (на основе L-уровней).
- Дизайн в едином стиле с diagnosis (Tailwind, чистые карточки, заголовки).
- Следование принципам из книги (временные горизонты, gate-критерии, акцент на среду).

## Out of Scope
- Backend / сохранение данных.
- Генерация через настоящий LLM (пока статическая + данные из levels).
- Поддержка R-уровней в roadmap (фокус на L, как в основных сценариях).

## Success Metrics
- Пользователь может быстро получить осмысленный roadmap за < 30 секунд после диагностики.
- Roadmap выглядит профессионально и полезно (команда захочет сохранить/распечатать).
- Соответствует описанию SR-2 из scenarios.md.
