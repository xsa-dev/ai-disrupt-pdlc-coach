# Design - Web Antipatterns Section

## High-level Structure

Страница `web/antipatterns.html` состоит из трёх частей + верхнее меню (как в roadmap.html).

### 0. Верхнее меню
- Ссылки: `Диагностика` (diagnosis.html), `Roadmap` (roadmap.html), `Антипаттерны` (antipatterns.html — активна).
- Справа: подпись `Disrupt PDLC Coach`.

### 1. Hero / Введение
- Заголовок «Антипаттерны трансформации».
- Подзаголовок: «Curriculum к успеху. Что не делать — и что делать вместо».
- Короткая легенда: антипаттерн = частая ошибка внедрения; для каждого дан признак и структурный фикс.

### 2. Секция «Частые в первый год» (7 подробных)
Источник: раздел 7.4, первый абзац + 7 описаний.
Для каждого — карточка:
- Название (например, «Полный цикл от вендора» / vendor lock-in)
- Блок «Признак раннего предупреждения»
- Блок «Структурный фикс» (что делать вместо)
- «Горизонт проявления» (Г1/Г2/Г3 — где указано)
- Иконка Font Awesome по смыслу.
Список 7: vendor lock-in; десятки директив вместо принципов; подмена модели вместо среды; vibe coding без оценок; big bang миграция; безграничный auto-approve; метрики без целей.

### 3. Секция «Полный реестр» (22 антипаттерна)
Источник: таблицы раздела 7.4 (№1–18 базовые, №19–22 управление).
- Фильтр-кнопки: «Все» / «Базовые» / «Управление».
- Сетка карточек: №, Название, Признак/Симптом, Митигация/Структурный фикс.
- Каждая карточка помечена типом (badge).

### 4. КВИЗ «К ВИЗ»
Интерактивный блок (чистый JS, без backend).

**Источник вопросов** — массив `QUIZ` (~58 вопросов), сгенерированный из 29 антипаттернов:
- По каждому антипаттерну 2 вопроса:
  - тип `name`: даётся признак/описание → выбрать правильное название АП.
  - тип `fix`: даётся название АП → выбрать правильный структурный фикс.
- Для каждого вопроса: `q` (текст), `correct` (правильный ответ-строка), `pool` (массив всех валидных вариантов этого типа), `explain` (почему верно).

**Data Model (JS):**
```js
const QUIZ = [
  { id, apId, type: 'name'|'fix', q, correct, pool:[...], explain },
  ...
];
const TICKET_SIZE = 10;
```

**Режимы:**
- «Случайный билет»: `shuffle(QUIZ)` → первые `TICKET_SIZE`. Показываем `Билет №<seed>` (seed = случайное число для воспроизводимости по нему же).
- «По билетам»: `ceil(N/TICKET_SIZE)` фиксированных билетов; Билет k = QUIZ[(k-1)*10 .. k*10-1]. Выбор номера билета из выпадающего списка. Состав стабилен между сессиями (порядок QUIZ фиксирован в коде).

**Логика прохождения:**
- Показываем вопросы по одному.
- 4 варианта (перемешаны из `pool`, но `correct` всегда включён).
- После выбора — сразу фидбек: зелёный/красный, `explain`.
- Кнопка «Далее».
- В конце — итог: «X из 10 верно» + кнопка «Пройти ещё раз» / «Другой билет».

## Visual Design
- Тот же Tailwind + emerald-акцент, что в roadmap.html.
- Карточки с мягкими границами (`rounded-3xl`, `border-slate-200`).
- Для антипаттернов — акцент на «опасности»: розово-красный для «чего не делать», emerald для «фикса».
- Мобильная адаптивность (grid `md:grid-cols-2/3`).
