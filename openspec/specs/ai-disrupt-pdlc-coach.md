# Disrupt PDLC Coach

## Overview

Внутренний Telegram-инструмент (агент-коуч), который помогает инженерным командам системно трансформировать процессы разработки по методологии **AI-Disrupt PDLC** (Whitepaper v2.0, Альвианский Алексей, Сбер).

Агент выступает в роли коуча и фасилитатора:
- Проводит диагностику зрелости команды.
- Помогает строить и отслеживать roadmap к L4–L5.
- Проектирует среду, практики и контур управления.
- Выдаёт структурированные артефакты.

**Центральный тезис (обязателен):** Модель задаёт минимально доступное качество. Среда работы определяет возможности того, что можно достичь.

## Requirements

### Core Principles (не нарушаются никогда)
- **Среда важнее модели** — при любых рекомендациях приоритет отдаётся улучшению среды (harness, контекст, инструменты, guardrails, валидация), а не смене модели.
- Человек — субъект петли намерения (Discovery + гипотеза результата).
- ИИ-агент — субъект петли реализации.
- **Governance Mesh** — третья ось PDLC, работает в реальном времени, а не постфактум.
- Валидация встроена (Evidence Bundle, агент-ревьюер), а не добавлена отдельной стадией.
- Честная оценка зрелости важнее "подталкивания" к высоким уровням.

### Functional Requirements

**FR-1. End-to-End Сценарии**
Агент должен вести пользователя по полным сценариям от начала до артефакта:
- Диагностика зрелости (L0–L5 + R0–R5 + task horizon)
- Построение Roadmap трансформации
- Проектирование конкретных элементов (среда, Guardian Agents, Governance, роли, валидация)
- Аудит текущих практик
- Регулярное сопровождение трансформации

**FR-2. Мультикомандность**
- Поддержка нескольких команд с изолированным контекстом.
- Сохранение профиля команды (текущий уровень, история диагностик, roadmap, артефакты).
- Возможность переключения между командами в Telegram.

**FR-3. Структурированные артефакты**
Генерация качественных Markdown-артефактов:
- Отчёты по диагностике
- Roadmap с этапами и gate-критериями
- Спецификации элементов
- Чек-листы и рекомендации

**FR-4. Следование книге**
- Использование точной терминологии из AI-Disrupt PDLC.
- Ссылки на разделы/принципы белой книги.
- Gate-критерии переходов между уровнями должны учитываться.

**FR-5. Telegram Interface**
- Удобные команды: /start diagnosis, /roadmap, /audit, /project, /status, /team
- Ведение диалога по шагам сценария.
- Сохранение состояния между сообщениями.

### Non-Functional Requirements
- Ответы агента должны быть честными (даже если уровень низкий).
- Хорошая производительность (ответы в разумное время).
- Легкость расширения знаниями из внутренних кейсов организации (отдельная коллекция).

## Architecture

### Основные компоненты
- **Knowledge Base (RAG)**: Структурированный поиск по whitepaper + будущие внутренние материалы. Метаданные: принцип, уровень зрелости, тип (паттерн/антипаттерн/метрика/пример).
- **Team Context Store**: Профиль команды, текущий roadmap, история артефактов.
- **Core Coach Agent**: Сильный system prompt + инструменты.
- **Tools**:
  - assess_maturity()
  - generate_roadmap(current, target)
  - evaluate_practice()
  - generate_element_spec()
  - save_artifact()
- **Telegram Layer**: Управление командами, сессиями сценариев, вывод Markdown.
- **Guardrails**: Проверка ответов на соответствие принципам книги.

### Уровни зрелости (использовать точно)
См. детальные профили L0–L5 и gate-критерии в приложениях плана.

### R0–R5
Риск-адаптивная лестница автономии агентов.

## Success Metrics
- Команды регулярно используют инструмент.
- Честность диагностик (команды не завышают уровень).
- Полезность и применение генерируемых артефактов.
- Соответствие принципам книги в рекомендациях.

## Non-Goals (Out of Scope для начальной версии)
- Полная замена живого коуча/консультанта.
- Автоматическое внедрение изменений в код/процессы без человека.
- Поддержка всех возможных AI-инструментов (фокус на Telegram + внутреннее использование).
- Сложная мультиагентная оркестрация до достижения устойчивого результата на базовом агенте.
